# OptimNet — ПО оптимизации живучести компьютерной сети

Десктопное приложение (Python + PyQt6), реализующее методику повышения
живучести компьютерной сети как задачу оптимизации. Методика описана в
[`doc/optim.md`](doc/optim.md): сеть — взвешенный ориентированный граф
G = ⟨V, E, C, W⟩, показатель живучести Ψ(x) = Σ p(s)·φ(Q(x, s)), частные
постановки 5.1–5.3 и аддитивная свёртка критериев (п. 6).

## Возможности

- **Модель данных**: узлы (маршрутизатор/коммутатор/сервер), каналы
  (ёмкость, стоимость, задержка, надёжность), потребности в трафике,
  кандидаты на резервирование (переменные x).
- **Сценарии поражения**: ручной редактор, загрузка из JSON/CSV,
  автогенерация случайных отказов каналов/узлов с заданными вероятностями.
- **Постановки задачи**:
  - 5.1 — максимизация Ψ при бюджетном ограничении;
  - 5.2 — минимизация стоимости при Ψ ≥ Ψ_треб и λ_ab ≥ r_ab;
  - 5.3 — робастная минимаксная по критическим сценариям;
  - свёртка Φ(x) = Σ α_k·F̃_k(x) с настраиваемыми весами α_k.
- **Алгоритмы** (единый интерфейс, новый алгоритм добавляется без правок UI):
  генетический алгоритм, имитация отжига, метод ветвей и границ,
  жадная эвристика.
- **Эксперимент**: запуск нескольких алгоритмов на одном наборе данных,
  сравнительная таблица (лучшее/среднее/худшее значение целевой функции,
  время, число итераций), график сходимости.
- Визуализация графа сети: базовые каналы, отказы сценария, найденные
  резервные каналы выделяются цветом.
- Длительные вычисления выполняются в фоновом потоке (QThread/pyqtSignal):
  интерфейс не блокируется, отображаются прогресс и текущее лучшее значение.
- Логирование хода оптимизации в файл `optimnet.log`.
- Тесты pytest на расчёт Q(x, s) и Ψ(x), проверку ограничений,
  кодирование/декодирование решения в ГА.

## Установка и запуск

### Windows

```bat
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

### Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python main.py
```

### Тесты

```bash
pytest tests/
```

## Форматы входных файлов

### Пример целиком (JSON): `examples/medium.json`

```json
{
  "nodes": [{"id": "R1", "kind": "router"}, {"id": "S1", "kind": "server"}],
  "links": [{"source": "R1", "target": "R2", "capacity": 10,
             "cost": 2.0, "delay": 0.0, "reliability": 0.99}],
  "demands": [{"source": "S1", "target": "S2", "volume": 8.0}],
  "candidates": [{"id": "C1", "source": "R1", "target": "R4",
                  "capacity": 10.0, "cost": 4.0}],
  "scenarios": [{"id": "S0", "p": 0.4, "failed_nodes": [], "failed_links": []},
                {"id": "S1", "p": 0.075, "failed_nodes": ["R2"],
                 "failed_links": [["R1", "R3"]]}]
}
```

- `nodes` — id и тип (`router` | `switch` | `server`);
- `links` — базовые каналы (источник, назначение, ёмкость; стоимость,
  задержка, надёжность — необязательны);
- `demands` — пары узлов с объёмом трафика (участвуют в расчёте Q);
- `candidates` — возможные резервные каналы (переменные решения x:
  выбран/не выбран и объём резервирования в [0, 1]);
- `scenarios` — сценарии поражения: вероятность `p`, отказавшие узлы
  `failed_nodes`, отказавшие каналы `failed_links`.

### CSV

Топология — каталог с файлами `nodes.csv`, `links.csv`, `demands.csv`,
`candidates.csv` (заголовки как в JSON). Сценарии — один файл:
`id,p,failed_nodes,failed_links`, где множества записываются через `;`,
а каналы в формате `ИСТОЧНИК-НАЗНАЧЕНИЕ`.

## Критерии приёмки (проверено)

1. `python -m venv .venv → pip install -r requirements.txt → python main.py`
   запускает GUI (команды для Windows и Linux — выше).
2. На среднем демо-примере постановка 5.1 решается минимум двумя
   алгоритмами, результаты сравниваются в таблице эксперимента.
3. Значения Ψ и Q в UI совпадают с результатами unit-тестов
   (оба используют `core.metrics`).
4. Вычисления не «замораживают» интерфейс: прогресс и лучшее значение
   обновляются в процессе оптимизации (QThread + сигналы).
