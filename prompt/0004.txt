# Задача: создать документацию на проект optimnet

## Роль
Ты — технический писатель и инженер-документатор. Необходимо разработать полную
документацию на существующее десктопное приложение optimnet (Python, PyQt6) —
инструмент оптимизации живучести компьютерной сети. Проект уже реализован, код
не меняется, кроме пункта 4 (комментарии в коде).

## Контекст
- Методика оптимизации описана в `doc/optim.md` — формальная модель сети,
  показатель живучести Ψ(x), постановки задачи (п. 5.1–5.3), свёртка критериев.
- Структура проекта:
  ```
  optimnet/
  ├── README.md
  ├── main.py                # точка входа
  ├── core/                  # модель сети, показатели, сценарии, ввод/вывод
  ├── algorithms/            # генетический алгоритм, имитация отжига,
  │                          # ветви и границы, жадная эвристика
  ├── gui/                   # окно PyQt6: вкладки «Топология», «Сценарии»,
  │                          # «Задача», «Алгоритм», «Эксперимент», «Результаты»
  ├── examples/              # демо-топологии: small.json, medium.json, large.json
  ├── tests/                 # pytest
  └── doc/                   # документация (сюда помещаются новые файлы)
  ```

## Цель
Подготовить комплект документации на русском языке: руководство пользователя,
руководство программиста, комментарии в исходном коде и схемы алгоритмов в SVG.

## Требования

### 1. Руководство пользователя — `doc/user_guide.md`
- Подробно описать **все элементы графического интерфейса**: каждую вкладку
  (gui/tab_problem.py, gui/tab_scenarios.py, gui/tab_algorithm.py,
  gui/tab_experiment.py, gui/tab_results.py, gui/graph_canvas.py),
  каждую кнопку, таблицу, поле ввода и их назначение.
- При описании интерфейса **каждый элемент пояснять скриншотом**: сделать снимки
  экрана реального запущенного приложения, вставить в документ рядом с описанием
  (картинки хранить в `doc/images/`).
- Привести **10 законченных примеров** использования системы. Каждый пример —
  пошаговый сценарий: цель → исходные данные (какой пример из examples/ или как
  ввести свои) → настройки задачи и алгоритма → запуск → ожидаемый результат →
  как прочитать результаты и график сходимости. Примеры должны покрывать:
  все три постановки (5.1, 5.2, 5.3), многокритериальную свёртку, все четыре
  алгоритма, сравнительный эксперимент и ручной ввод топологии со сценариями.

### 2. Руководство программиста — `doc/developer_guide.md`
- Описать **архитектуру и принципы построения проекта**: слои (core → algorithms
  → gui), поток данных от ввода топологии до вывода результата, единый интерфейс
  оптимизатора, устройство фоновых вычислений (QThread/pyqtSignal).
- Подробно описать **структуру проекта**: назначение каждого модуля и ключевых
  классов/функций (с указанием файлов и сигнатур).
- Описать форматы входных/выходных файлов (JSON-топологии, CSV-экспорт),
  порядок добавления нового алгоритма, порядок запуска тестов.

### 3. Схемы алгоритмов — `doc/svg/`
- Каждый алгоритм оформить **отдельным SVG-файлом** блок-схемы: генетический
  алгоритм, имитация отжига, метод ветвей и границ, жадная эвристика, а также
  общая схема работы приложения. Подписи на схемах — на русском языке.

### 4. Комментарии в коде
- Добавить в исходный код **комментарии на русском языке**: докстринги к модулям,
  классам и публичным методам, поясняющие комментарии к нетривиальным участкам
  (расчёт Ψ, кодирование хромосомы, охлаждение в отжиге). Поведение кода
  не изменять.

### 5. Общие требования
- Вся документация — **только на русском языке**, оформление — Markdown.
- Все файлы документации — в каталоге `doc/` (скриншоты в `doc/images/`,
  схемы в `doc/svg/`). При необходимости обновить `README.md` со ссылками
  на новые документы.
- Терминология и обозначения должны совпадать с `doc/optim.md` и с текстом
  интерфейса приложения.

## Порядок работы
1. Изучи `doc/optim.md`, исходный код проекта и интерфейс (запусти `main.py`).
2. Составь план документации и согласуй структуру файлов.
3. Подготовь схемы алгоритмов (SVG), затем руководство программиста.
4. Запусти приложение, сделай скриншоты, напиши руководство пользователя
   с 10 примерами.
5. Добавь комментарии в код и проверь, что тесты (`pytest`) проходят.

## Критерии приёмки
- Файлы `doc/user_guide.md`, `doc/developer_guide.md` и SVG-схемы в `doc/svg/`
  существуют и открываются.
- В руководстве пользователя описаны все вкладки и элементы GUI, каждый пример
  (их ровно 10) воспроизводим: выполнение шагов на приложении даёт описанный
  результат.
- Каждый описанный элемент интерфейса проиллюстрирован скриншотом из
  `doc/images/`.
- После добавления комментариев `pytest` проходит без ошибок, приложение
  запускается.
