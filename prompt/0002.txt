# Задача: разработка ПО оптимизации живучести компьютерной сети

## Роль
Ты — инженер-разработчик (Python, PyQt). Необходимо спроектировать и реализовать с нуля
десктопное приложение, реализующее методику повышения живучести компьютерной сети
как задачу оптимизации.

## Контекст
Методика описана в файле `doc/optim.md`. Перед началом работы внимательно изучи его:
там приведены формальная модель сети (взвешенный ориентированный граф G = ⟨V, E, C, W⟩),
показатель живучести Ψ(x), частные постановки задачи (п. 5.1–5.3), свёртка критериев (п. 6)
и предполагаемые алгоритмы (п. 8, глава 3). Все формулы и обозначения бери из этого
документа; при расхождениях в трактовке — следуй тексту `doc/optim.md`.

## Цель
Приложение должно позволять пользователю: задать топологию сети и сценарии отказов,
выбрать постановку задачи оптимизации, запустить алгоритм решения, получить и сравнить
результаты (в том числе наглядно, на графе сети).

## Функциональные требования

### 1. Модель данных
- Сеть — ориентированный взвешенный граф G = ⟨V, E, C, W⟩: узлы (маршрутизатор /
  коммутатор / сервер) и каналы (ёмкость c_ij, стоимость, задержка, надёжность).
- Сценарий поражения s: набор отказавших узлов/каналов + вероятность p(s).
  Поддержать: ручной ввод, загрузку из файла, автогенерацию случайных отказов
  с заданной вероятностью.
- Хранение топологий и сценариев в JSON/CSV. Поставить ≥3 демонстрационных примера:
  малый (5–7 узлов), средний (~10 узлов), большой (~20 узлов).
- Вектор решения x: набор резервных каналов и/или объёмы резервирования —
  дискретные и непрерывные переменные (смешанный случай из п. 2 `doc/optim.md`).

### 2. Расчёт показателей (п. 2–3 `doc/optim.md`)
- Качество Q(x, s): доля доставленного трафика (максимальный поток между заданными
  парами узлов) и/или индикатор связности критических пар — вариант выбирается
  в настройках задачи.
- Живучесть Ψ(x) = Σ p(s)·φ(Q(x, s)), где φ — пороговая функция с настраиваемым Q_min.
- Стоимость C_Σ(x), среднее качество Q̄(x), время восстановления (упрощённая модель
  по числу и весу отказавших элементов, параметры настраиваются).
- Проверка ограничений: бюджет C_Σ ≤ C_бюдж, неперегрузка каналов, связность
  приоритетных пар λ_ab ≥ r_ab.

### 3. Постановки задачи (п. 5–6 `doc/optim.md`)
Реализовать все три частные постановки:
- 5.1 — максимизация Ψ(x) при бюджетном ограничении;
- 5.2 — минимизация стоимости при Ψ(x) ≥ Ψ_треб и требованиях связности;
- 5.3 — робастная минимаксная постановка по критическим сценариям.
Многокритериальный случай — аддитивная свёртка Φ(x) = Σ α_k·F̃_k(x) с нормировкой
критериев и настраиваемыми весами α_k.

### 4. Алгоритмы (глава 3 `doc/optim.md`)
- Генетический алгоритм: кодирование хромосомы под смешанный дискретно-непрерывный
  вектор, турнирная селекция, кроссинговер, мутация, элитизм. Параметры (размер
  популяции, число поколений, вероятности) настраиваются в UI.
- Имитация отжига: T_0, скорость охлаждения, число итераций — настраиваются в UI.
- Метод ветвей и границ (для малых экземпляров; порог размера настраивается).
- Жадная эвристика как базовый ориентир для сравнения.
- Единый интерфейс оптимизатора: добавление нового алгоритма не должно требовать
  правок в UI.
- Длительные вычисления не блокируют интерфейс (QThread/pyqtSignal), отображаются
  прогресс и текущее лучшее значение целевой функции.

### 5. Графический интерфейс (PyQt6, язык — русский)
- «Топология»: редактируемые таблицы узлов и каналов, визуализация графа; каналы
  найденного решения (резервные) выделяются цветом.
- «Сценарии»: список сценариев, редактор, генератор случайных отказов.
- «Задача»: выбор постановки (5.1 / 5.2 / 5.3 / свёртка), веса α_k, Q_min, бюджет,
  перечень приоритетных пар узлов.
- «Алгоритм»: выбор алгоритма и его параметров.
- «Эксперимент»: запуск нескольких алгоритмов на одном наборе данных, сравнительная
  таблица (лучшее / среднее / худшее значение целевой функции, время работы,
  число итераций) и график сходимости (matplotlib, встроенный в окно).
- «Результаты»: найденное решение x, значения всех критериев, экспорт в CSV/JSON.

## Технические требования
- Python ≥ 3.10. GUI — PyQt6.
- Зависимости: numpy, networkx, matplotlib; для тестов — pytest. Другие библиотеки —
  только при реальной необходимости.
- Приложение работает в изолированном окружении: запуск из venv, шаги установки
  описаны в README (отдельно для Windows и Linux).
- Предложи и обоснуй структуру проекта по аналогии с:
  ```
  optimnet/
  ├── README.md            # установка, запуск, форматы входных файлов
  ├── requirements.txt
  ├── main.py
  ├── core/                # модель сети, показатели, сценарии
  ├── algorithms/          # оптимизаторы
  ├── gui/                 # окна PyQt
  ├── examples/            # демо-топологии и сценарии
  └── tests/               # pytest
  ```
- Логирование хода оптимизации в файл.
- Тесты pytest как минимум на: расчёт Q(x, s) и Ψ(x), проверку ограничений,
  корректность кодирования/декодирования решения в генетическом алгоритме.

## Порядок работы
1. Изучи `doc/optim.md`, кратко перескажи понимание постановки, предложи структуру
   проекта и план работ.
2. Реализуй core (модель, показатели, сценарии) и тесты к нему.
3. Реализуй алгоритмы, проверь их на демо-примерах.
4. Реализуй GUI и собери приложение целиком.
5. Выполни финальную проверку по критериям приёмки.

## Критерии приёмки
- Последовательность «создать venv → pip install -r requirements.txt → python main.py»
  приводит к запуску GUI (команды для Windows и Linux приведены в README).
- На среднем демо-примере решается постановка 5.1 минимум двумя алгоритмами,
  результаты сравниваются в таблице эксперимента.
- Значения Ψ и Q, показанные в UI, совпадают с результатами unit-тестов.
- Вычисления не «замораживают» интерфейс: прогресс и лучшее значение обновляются
  в процессе оптимизации.
